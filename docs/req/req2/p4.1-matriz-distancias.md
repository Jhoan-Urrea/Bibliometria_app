## Contrato

`com.bibliometria.core.clustering.DistanceMatrix` construye una matriz cuadrada e inmutable para
los veinte `ProcessedDocument` del corpus de referencia. Consume `TfIdfSimilarity` del módulo
`core`; no introduce dependencias de producción fuera del JDK. Las filas y columnas quedan
ordenadas por identificador ascendente, independientemente del orden de entrada.

## Definición y correspondencia fórmula-código

Para cada par de documentos \(x,y\), la distancia es
\[
\delta(x,y)=1-\operatorname{sim}_{\cos}(u_x,u_y),
\qquad
\operatorname{sim}_{\cos}(u_x,u_y)=
\frac{u_x\cdot u_y}{\lVert u_x\rVert_2\lVert u_y\rVert_2},
\]
donde \(u_x,u_y\) son los vectores TF-IDF definidos por `TfIdfSimilarity` con el corpus global de
20 documentos. El constructor evalúa una vez cada par de índices \(i<j\), almacena
\(1-\texttt{normalizado}\) y copia el mismo valor a las posiciones \((i,j)\) y \((j,i)\). La
diagonal se asigna exactamente a cero.

La similitud de vectores vacíos sigue la convención vigente de `TfIdfSimilarity`: dos vectores
cero se consideran idénticos (similitud 1, distancia 0); si solo uno es cero, la similitud es 0
(distancia 1).

## Validación e inmutabilidad

`validar()` comprueba que la matriz sea cuadrada, simétrica dentro de \(10^{-12}\), tenga diagonal
exactamente cero y contenga únicamente valores finitos dentro de \([0,1]\). Durante la
construcción, desviaciones de precisión flotante de hasta \(10^{-12}\) en los límites se recortan
a 0 o 1; valores no finitos o fuera de tolerancia fallan explícitamente. Los IDs se exponen como
lista inmutable y `toArray()` devuelve una copia profunda para que el consumidor no pueda alterar
el estado interno.

## Pruebas y ejecución

`core/src/test/java/com/bibliometria/core/clustering/DistanceMatrixTest.java` verifica límites,
simetría, diagonal, cálculo de distancias de referencia, orden y contenido deterministas,
inmutabilidad de la copia exportada y rechazo de corpus/IDs inválidos.

```sh
mvn -pl core -Dtest=DistanceMatrixTest test
mvn clean verify
```

## P4.2 — Criterios de enlace

`Linkage.update(dAC, dBC, dAB, sizeA, sizeB)` implementa la recurrencia de Lance–Williams:
\[
d(A\cup B,C)=\alpha_A d(A,C)+\alpha_B d(B,C)+\beta d(A,B)
+\gamma |d(A,C)-d(B,C)|.
\]

- `SingleLinkage`: \(\alpha_A=\alpha_B=0.5,\beta=0,\gamma=-0.5\), equivalente a
  \(\min(d(A,C),d(B,C))\).
- `CompleteLinkage`: \(\alpha_A=\alpha_B=0.5,\beta=0,\gamma=0.5\), equivalente a
  \(\max(d(A,C),d(B,C))\).
- `AverageLinkage` (UPGMA): \(\alpha_A=|A|/(|A|+|B|)\),
  \(\alpha_B=|B|/(|A|+|B|)\), \(\beta=\gamma=0\); el promedio pondera por cantidad de hojas.

Las clases rechazan tamaños no positivos, distancias no finitas/fuera de `[0,1]` y actualizaciones
fuera del rango salvo ruido numérico de hasta \(10^{-12}\), que se recorta al límite.

## P4.3 — Clustering aglomerativo

`AgglomerativeClustering.run(matrix, linkage)` comienza con una hoja por fila de la matriz y
repite \(n-1\) veces: selecciona el par activo de menor distancia, actualiza sus distancias con
Lance–Williams y registra `Merge(leftChild, rightChild, height, size)`. Hojas usan índices
`0..n-1`; cada clúster nuevo recibe `n + mergeNumber`. Los hijos se guardan en orden ascendente.
Ante distancias idénticas se elige lexicográficamente el par de índices activos menor, haciendo el
resultado reproducible.

`AgglomerativeClusteringTest` verifica un fixture autocontenido de cuatro elementos
`d(AB)=0.1,d(AC)=0.4,d(AD)=0.7,d(BC)=0.5,d(BD)=0.8,d(CD)=0.3`; las alturas finales son
`0.4` (single), `0.8` (complete) y `0.6` (UPGMA). Incluye empates exactos y 1.000 casos aleatorios
de equivalencia min/max, además de jerarquías aleatorias repetibles y monotónicas. Los valores del
fixture son de prueba y no se presentan como transcripción del ejemplo numérico del DF.

```sh
mvn -pl core -Dtest=AgglomerativeClusteringTest,DistanceMatrixTest test
mvn clean verify
```

## P4.4 — Dendrograma y matriz cofenética

`Dendrogram.from(matrix, merges)` materializa la secuencia completa de `N-1` fusiones como un
árbol binario inmutable. Las hojas conservan los IDs e índices canónicos de `DistanceMatrix`; cada
nodo interno contiene sus hijos, la altura de fusión y el tamaño del clúster. La secuencia se
valida: los hijos deben estar activos, el tamaño debe coincidir con ambos subárboles y las alturas
no pueden decrecer por más de \(10^{-12}\). Si solo existe ruido de redondeo dentro de esa
tolerancia, la altura almacenada se eleva a la altura de hijo mayor para preservar la propiedad
ultramétrica. Los hijos del árbol se orientan por el menor índice hoja, por lo que `leafOrder()`
devuelve el orden canónico de documentos.

Para hojas \(x,y\), la distancia cofenética es
\[
h(x,y)=\operatorname{altura}(\operatorname{LCA}(x,y)),
\]
donde \(\operatorname{LCA}\) es su ancestro común más bajo, es decir, la fusión en la que pasan a
pertenecer al mismo clúster. `Dendrogram.copheneticMatrix()` recorre cada subárbol en postorden.
Para cada nodo interno, asigna su altura a todos los pares formados por una hoja del hijo izquierdo
y una del derecho, en ambas posiciones de la matriz. Cada par de hojas queda asignado exactamente
una vez en su LCA; el número total de asignaciones cruzadas es \(\binom{N}{2}\), por lo que el
cálculo es \(O(N^2)\). `CopheneticMatrix` es inmutable, simétrica, tiene diagonal cero y expone
acceso por índice o ID y una copia defensiva de sus datos.

`DendrogramTest` valida las alturas cofenéticas del fixture de cuatro documentos (A-B: `0.1`,
C-D: `0.3`, pares entre ambos clústeres: `0.4` con enlace single), simetría, diagonal y
ultrametricidad \(h(x,y)\leq\max(h(x,z),h(z,y))\) para cada terna, además de árbol unitario,
inmutabilidad y rechazo de historiales inválidos.

```sh
mvn -pl core -Dtest=DendrogramTest,AgglomerativeClusteringTest,DistanceMatrixTest test
mvn clean verify
```

## P4.5 — Correlación cofenética (CPCC)

`CopheneticCorrelation.compute(delta, dendrogram)` calcula el coeficiente de Pearson entre las
distancias originales \(\delta_{ij}\) y las alturas cofenéticas \(h_{ij}\) de los
\(M=N(N-1)/2\) pares no ordenados:
\[
r_c=\frac{\sum_{i<j}(\delta_{ij}-\bar\delta)(h_{ij}-\bar h)}
{\sqrt{\sum_{i<j}(\delta_{ij}-\bar\delta)^2
\sum_{i<j}(h_{ij}-\bar h)^2}}.
\]
En dos recorridos \(O(N^2)\) y espacio auxiliar \(O(1)\), el primero obtiene ambas medias y el
segundo las sumas centradas. Si cualquiera de las series tiene varianza cero (incluido \(N<2\)),
retorna `0.0`, según la convención del DF. La matriz y el dendrograma deben tener los mismos IDs
canónicos.

La prueba usa un fixture autocontenido de cuatro hojas para el que Single Linkage produce
\(r_c\approx0.8985\). No se declara que las distancias concretas sean una transcripción del ejemplo
numérico del DF.

## P4.6 — Corte del árbol y silueta

`ClusterCut.cut(merges,k,numLeaves)` conserva las primeras \(N-k\) fusiones y omite las últimas
\(k-1\). Una estructura Union-Find une las hojas de los clústeres conservados; las etiquetas
resultantes son consecutivas `0..k-1`, ordenadas por índice canónico mínimo de hoja. La entrada
debe ser un historial completo y coherente con la convención de IDs de `AgglomerativeClustering`.

Para cada hoja \(x\), `Silhouette.perDocumentScores` calcula la cohesión \(a(x)\) como la distancia
media a las otras hojas de su clúster y la separación \(b(x)\) como la menor distancia media a
cualquiera de los otros clústeres:
\[
s(x)=\frac{b(x)-a(x)}{\max(a(x),b(x))}.
\]
`Silhouette.score` devuelve el promedio aritmético de \(s(x)\) para todos los documentos. Se
aceptan de 2 a 10 clústeres observados. Una hoja en un clúster unitario, o el caso
\(a(x)=b(x)=0\), recibe silueta `0`; la salida nunca contiene NaN. El cálculo acumula distancias
de pares y después evalúa las medias por clúster, con tiempo \(O(N^2+NK)\) y espacio adicional
\(O(NK)\); aquí \(K\leq10\) por contrato.

`ClusterCutTest` valida cortes en \(K=1,2,3,N\), etiquetas canónicas e historiales inválidos.
`SilhouetteTest` compara el resultado y valores por documento con dos grupos sobre una recta,
además de los casos unitario, distancias nulas y límites de \(K\).
`CopheneticCorrelationTest` valida el caso de cuatro hojas (\(\approx0.8985\)), varianza cero y
desacuerdo de IDs.

```sh
mvn -pl core -Dtest=CopheneticCorrelationTest,ClusterCutTest,SilhouetteTest test
mvn clean verify
```

## P4.8 — Evaluación y regla de decisión

`ClusteringEvaluationService.evaluate(delta)` ejecuta Single, Complete y Average Linkage. Para cada
árbol calcula el CPCC y \(S(K)\) para \(K=2,\ldots,\min(10,N)\), selecciona el K con mayor silueta
media y conserva también todas las puntuaciones. Si varios K de un mismo enlace difieren por no más
de \(10^{-9}\), se escoge el K menor para evitar fragmentación innecesaria.

La selección global aplica ADR-013: gana la solución con mayor \(S(K)\); si las siluetas difieren
en no más de \(10^{-9}\), gana el mayor CPCC. Si ambos valores empatan, el orden reproducible es
Single, Complete, Average. El resultado inmutable incluye cada secuencia de fusiones, dendrograma,
CPCC, mejor K y el mapa \(S(K)\). Se exige \(N\geq2\).

## P4.11 — Exportación JSON para la interfaz

`tools` contiene `ClusteringExportCommand` y `ClusteringJsonExporter`; Jackson permanece en
`tools`, sin añadir dependencias productivas a `core`. El comando consume un arreglo de corpus JSON
con `id`, `title`, `authors`, `abstractText` y `verified:true`, aplica `TextPreprocessor`, construye
la matriz TF-IDF y exporta la evaluación de los tres enlaces.

El documento JSON incluye la regla/selección final, métricas y valores \(S(K)\) por enlace, filas
`Merge` (`leftChild`, `rightChild`, `height`, `size`), orden de hojas con ID/título/autores y un
árbol binario recursivo compatible con D3 (`id`, `name`, `height`, `size`, `children`). Cada hoja
incluye `documentId`, título, autores y etiqueta del corte en el mejor K. La ruta de salida se crea
si aún no existe.

```sh
mvn -pl tools -am package
mvn -pl tools dependency:build-classpath -Dmdep.outputFile=/tmp/bibliometria-tools.classpath
java -cp "tools/target/classes:core/target/classes:$(cat /tmp/bibliometria-tools.classpath)" \
  com.bibliometria.tools.clustering.ClusteringExportCommand \
  data/corpus.json data/clustering.json
mvn clean verify
```

`ClusteringEvaluationServiceTest` comprueba métricas por enlace, mejor K, desempate CPCC con
tolerancia \(10^{-9}\), la prioridad de silueta fuera de tolerancia y orden determinista.
`ClusteringJsonExporterTest` valida parseabilidad y estructura D3 del JSON, metadatos y una
ejecución del comando sobre 20 registros verificados.
